# Contributing to AetherAssembly

Thanks for considering a contribution. This is the org-wide default; if a repo has its own CONTRIBUTING.md, follow that one instead since it'll have project-specific setup steps.

## General flow

1. Check open issues first, someone may already be working on it
2. Fork the repo and branch off the default branch
3. Make your changes, keep commits focused
4. Run whatever lint/test/build scripts the repo defines before opening a PR
5. Open a PR against the default branch and fill out the template

## Commit style

Keep messages short and descriptive. No strict convention enforced, but "fix: crash on empty input" beats "changes".

## Code style

Match whatever's already in the file. Most repos use ESLint/Prettier configs, run those before committing.

## Reporting bugs or requesting features

Use the issue templates. Include steps to reproduce for bugs, and the problem you're trying to solve for feature requests.

## Questions

Email [support@aetherassembly.org](mailto:support@aetherassembly.org) (app and dev help) or open a discussion if the repo has one enabled.
