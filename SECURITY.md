# Security Policy

## Reporting a Vulnerability

Please do not disclose security vulnerabilities in public issues.

Use GitHub private vulnerability reporting if enabled on the repo in question, or contact us through one of the following:

- Email: [support@aetherassembly.org](mailto:support@aetherassembly.org)
- Contact form: [https://forms.gle/T4i7GGzaT3HUrffm9](https://forms.gle/T4i7GGzaT3HUrffm9)
- Aster (GitHub): [@Aster1630](https://github.com/Aster1630)

Please include in your report:

- A clear description of the issue
- Steps to reproduce
- Impact assessment
- Any suggested remediation or workaround

You can expect an initial acknowledgement within 7 days of receipt. After validation, the maintainers will work on a fix and coordinate disclosure timing as appropriate.

## Supported Versions

Support windows vary by project. Check the individual repo's README or CHANGELOG for its current supported version range. As a general rule, the current release and the two most recent major versions receive active security fixes; anything older is acknowledged but not actively patched.

## Scope

This applies across all AetherAssembly projects: packaged desktop apps, browser extensions, and published npm packages. Relevant areas generally include dependency vulnerabilities, unsafe filesystem or shell execution, local data handling, and packaged release artifacts.

## Non-Security Issues

General bugs, feature requests, packaging problems, and compatibility issues should go through the normal issue tracker on the relevant repo.
